# Тесты — сайт тематических тестов

Сайт коротких тематических тестов для аудитории 45+/55+. Рабочее название продукта — **«Тесты»**; «Тесты и квизы» — только имя папки и репозитория.

В репозитории — продуктовые документы и рабочая реализация Sprint 1–2: каркас Next.js, авторизация по email, каталог тем, интересы, тренировки на 10/15/20/30 вопросов, готовые выпуски на 10–12 вопросов, «Тест дня», серверная проверка ответов, прогресс по темам, повторение ошибок, «Мои результаты», шаринг результата с OG-карточкой, служебная админка с ролями, CRUD тем и вопросов, импорт JSON с предпросмотром, cookie-баннер с аудитом согласий, экспорт данных, удаление аккаунта, dev-почтовый ящик и сквозные тесты.

## Кратко о продукте

**Аудитория:** по статистике тестов в Дзене ~74% зрителей старше 45 лет, ядро — 55+. Поэтому продукт проектируется в первую очередь под взрослую аудиторию: крупный текст, спокойный темп, уважительный тон, без таймера и без молодёжного сленга.

Сайт коротких тематических тренировок (10–30 вопросов), в котором:

- каталог и темы открыты без входа, а тренировка и прогресс сохраняются после входа;
- прогресс ведётся не только по тренировкам, но и **по темам и отдельным вопросам**;
- есть баллы, уровень, серия дней и наглядная статистика;
- ошибки возвращаются в очередь повторения, а «Мои результаты» показывают, что уже освоено;
- контент приходит из уже существующего конвейера `forms_writer` (LLM + факт-чек + ревью + дедуп); сейчас в репозитории — демо-набор;
- авторизация переиспользует проверенный подход `autocard-pro` (email + scrypt + httpOnly-cookie + подтверждение email + rate-limit).

## Ключевое продуктовое решение

**Не выбирать между «отдельными тестами» и «бесконечным банком вопросов».** Используем гибрид:

1. **Тренировка** — 10/15/20/30 вопросов из темы или раздела, знакомый формат.
2. **Готовый выпуск** — 10–12 вопросов внутри темы и постоянная ссылка.
3. **Банк вопросов темы** — вопросы живут отдельно и переиспользуются.
4. **Прогресс** — по вопросу (освоение 0–5) → по теме (изученность/точность/уровень) → глобальный (баллы/уровень/серия дней).

Готовые выпуски уже работают: их можно открыть из темы и отправить ссылкой. Тренировка остаётся свободным выбором длины и глубины.

## Быстрый старт (≤ 10 минут)

Требования: Node.js 24 LTS, npm 11+, Docker Desktop.

```powershell
# 0. Клонирование (если репозиторий ещё не склонирован)
git clone <url> "Тесты и квизы"
cd "Тесты и квизы"

# 1. Зависимости
npm ci

# 2. Конфигурация: скопируйте шаблон и заполните AUTH_SECRET
Copy-Item .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
#    вставьте значение в AUTH_SECRET=.env

# 3. PostgreSQL в Docker (том и healthcheck уже настроены)
npm run db:up

# 4. Миграции и демо-контент
npm run db:deploy
npm run db:seed

# 5. Запуск
npm run dev
```

Откройте `http://localhost:3000`. Если порт 5432 занят, задайте `DB_PORT=5433` в `.env` и поправьте порт в `DATABASE_URL` (в репозитории разработчика используется 5433).

Письма в dev-режиме не отправляются наружу: они пишутся в `logs/dev-mail.log` и доступны на `http://localhost:3000/_dev/mailbox`.

### Импорт контента

Импорт принимает JSON `forms_writer` и не меняет схему БД:

```powershell
# Посмотреть план без записи
npm run db:import -- --file ../forms_writer/samples/questions.json --dry-run

# Загрузить вопросы вместе с новыми темами из маппинга
npm run db:import -- --file ./batch-2026-11.json --create-topics

# Загрузить только если вся партия валидна (для CI)
npm run db:import -- --file ./batch.json --strict
```

Правила:

- тема из файла переводится в раздел и тему каталога через `scripts/import/topic-map.json`; неизвестная тема — ошибка;
- дубликаты определяются по `contentHash`, который не зависит от порядка вариантов, поэтому повторный импорт ничего не создаёт;
- вопрос без объяснения сохраняется как `DRAFT` и не показывается пользователям, а уже опубликованный вопрос черновик не снимает с публикации;
- изменение вариантов или правильного ответа создаёт новую версию: старая формулировка уходит в `ARCHIVED`; изменение текста — новый вопрос с предупреждением о похожем тексте, разбирает его редактор;
- если в теме появился реальный опубликованный вопрос, демо-вопросы этой темы скрываются (`ARCHIVED`), а не удаляются; `TopicProgress` пересчитывается;
- `--dry-run` показывает отчёт «создано / обновлено / новых версий / пропущено / черновиков» без записи, `--report <path>` сохраняет JSON-отчёт, `--strict` откатывает партию при ошибке.

Подробности и критерии приёмки — [`docs/tasks/04-content-import.md`](docs/tasks/04-content-import.md).

### Админка и роли

Служебный раздел `/admin` открыт только ролям `EDITOR` и `ADMIN`. Гость уходит на
`/login?next=%2Fadmin`, обычный пользователь получает `404`. Редактор видит темы,
вопросы, выпуски и импорт; администратор дополнительно — пользователей и
аналитику.

Роль выдаётся из терминала, без публичного HTTP-эндпоинта:

```powershell
npm run user:role -- user@example.com EDITOR
npm run user:role -- user@example.com ADMIN
npm run user:role -- user@example.com USER
```

Команда идемпотентна: повторный запуск с той же ролью ничего не ломает. При
следующем запросе роль читается из БД, повторный вход не нужен. Подробности —
[`docs/tasks/07-admin.md`](docs/tasks/07-admin.md).

### Управление контентом в админке

Раздел «Темы и вопросы» (`/admin/topics`) даёт редактору и администратору:

- создать тему: название, адрес (подставляется транслитерацией из названия),
  раздел, описание, обложка, порядок и статус;
- добавить вопрос: текст, четыре варианта, один правильный ответ, объяснение,
  сложность, изображение и статус;
- опубликовать или убрать в архив тему и вопрос. Физического удаления нет:
  на вопрос ссылаются попытки, ответы и прогресс, поэтому «удаление» — это
  `ARCHIVED`;
- изменить опубликованный вопрос. Если меняются текст, варианты или правильный
  ответ, старая версия уходит в архив, а новая получает следующий номер.
  Объяснение, сложность и изображение правятся на месте.

Раздел «Импорт» (`/admin/import`) принимает JSON `forms_writer` в выбранную
тему. Сначала показывается предпросмотр — что добавится, обновится, получит
новую версию или будет пропущено, — и только после подтверждения вопросы
пишутся в базу. Поле `topic` внутри файла не создаёт темы: тема выбирается в
интерфейсе. Лимит — 500 вопросов и 1 МБ тела запроса.

Админские API живут отдельно в `/api/v1/admin/*`, публичный API каталога не
менялся. Гость получает `401`, обычный пользователь — `404`; мутации проверяют
Origin и rate-limit. Подробности и коды ошибок —
[`docs/tasks/08-admin-content.md`](docs/tasks/08-admin-content.md).

### Cookie и согласия

Cookie-баннер показывается на всех страницах, пока выбор не сделан. Он стоит в
потоке страницы под шапкой и не перекрывает кнопки и текст — важно для
аудитории 55+.

| Категория | По умолчанию | Что делает |
| --- | --- | --- |
| Необходимые | включены | Вход, безопасность, выбранный размер текста |
| Аналитика | выключена | Обезличенная статистика посещений |
| Реклама и партнёры | выключена | Персональные предложения и партнёрские материалы |

- «Только необходимые» и «Принять все» — равнодоступные крупные кнопки;
  отдельная кнопка «Настроить» открывает категории.
- Выбор хранится в cookie `quiz_cookie_consent` 180 дней. При смене
  `LEGAL_COOKIES_VERSION` согласие спрашивается заново.
- Для вошедшего пользователя обе категории пишутся в `Consent`
  (`COOKIE_ANALYTICS`, `COOKIE_MARKETING`) при каждом сохранении, включая
  отказ. Гость остаётся только в cookie.
- Отозвать согласие можно на [`/legal/cookies`](app/legal/cookies/page.tsx):
  кнопка открывает настройки повторно.
- Аналитических и рекламных сервисов сейчас нет: переключатели готовят контур
  на будущее и ничего не загружают без согласия.

API — `POST /api/v1/cookies/consent` с телом `{ "analytics": true, "marketing": false }`.
Same-origin, Zod, rate-limit 60/час на пользователя и IP, ответ `no-store`.
Подробности — [`docs/tasks/09-cookie-consent.md`](docs/tasks/09-cookie-consent.md).

### Данные и аккаунт

На странице «Мои результаты» (`/account`) есть блок «Данные и аккаунт»:

- **Скачать все данные (JSON)** — профиль, согласия, интересы, попытки со всеми
  ответами, прогресс по вопросам и темам, статистика и активность по дням.
  Все даты — ISO 8601, пароль и его хеш не выгружаются никогда.
- **История тренировок (CSV)** — таблица для Excel: UTF-8 с BOM, разделитель
  `;`, переводы строк CRLF, русские подписи режимов и статусов.
- **Удалить аккаунт** — отдельная страница `/account/delete`, не модальное
  окно. Нужны текущий пароль, слово `УДАЛИТЬ` (регистр не важен) и чекбокс
  понимания последствий; рядом ссылки «скачать данные» и «вернуться».

Удаление — анонимизация, а не физическое стирание: email заменяется на
`deleted-<id>@deleted.invalid`, пароль, имя, аватар и подтверждение почты
обнуляются, `sessionEpoch` растёт и все сессии закрываются. `AuthIdentity`,
`EmailToken` и `UserInterest` удаляются, у `Consent` обнуляются IP и
User-Agent. Попытки, ответы, прогресс и агрегированная статистика остаются
обезличенными (§9.4 ТЗ). Событие `account.deleted` пишется в `AuditLog` без
персональных данных.

API — `GET /api/v1/me/export` (`?format=csv`), `DELETE /api/v1/me`.
Same-origin, Zod, rate-limit удаления 5/час, ответы `no-store`.
Подробности — [`docs/tasks/10-account-deletion.md`](docs/tasks/10-account-deletion.md).

### Шаринг результата

На экране завершённой тренировки есть блок «Поделиться результатом»:
системное окно «Поделиться» (на телефонах), копирование ссылки и мессенджеры
Telegram, WhatsApp, Одноклассники, ВКонтакте.

- Ссылка ведёт на публичную страницу `/share/<attemptId>/<токен>`, которая
  открывается **без входа**.
- На странице только итог: название теста, процент, число верных ответов и дата.
  Почта, имя и ответы не показываются.
- Токен — усечённый HMAC-SHA256 от id попытки (`AUTH_SECRET`), в БД не хранится,
  миграции нет. Один результат — один стабильный адрес.
- Шарятся только завершённые попытки; прерванная и подделанная ссылка дают `404`.
- Страницы `noindex, nofollow`; в соцсетях и мессенджерах показывается
  OG-карточка 1200×630 с кириллицей (шрифт Golos Text в `assets/fonts`).
  У остальных страниц — общая карточка сайта.
- Отозвать отдельную ссылку пока нельзя: убрать блок — значит скрыть только
  новые ссылки, а смена `AUTH_SECRET` обнуляет все выданные (и все сессии).
  Отзыв появится вместе с настройками приватности.

Подробности и откат — [`docs/tasks/11-sharing.md`](docs/tasks/11-sharing.md).

### E2E локально

Playwright поднимает сервер с `DATABASE_URL_TEST`, поэтому тестовую БД нужно мигрировать и засеять отдельно:

```powershell
npm run db:test:up
npm run db:test:deploy
$env:DATABASE_URL = (Get-Content .env | Where-Object { $_ -match '^DATABASE_URL_TEST=' } | Select-Object -First 1).Substring('DATABASE_URL_TEST='.Length)
npm run db:seed
npm run test:e2e
```

Перед e2e остановите `npm run dev`: Playwright переиспользует уже запущенный сервер (`reuseExistingServer`), а он может смотреть в dev-БД. В CI сервер поднимается командой `npm run start` с `APP_ENV=test`; шаг `db:seed` выполняет workflow.
