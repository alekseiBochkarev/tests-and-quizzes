# AGENTS.md — правила работы с репозиторием «Тесты и квизы»

## Главное правило: git — только владелец проекта

**Коммиты и push делает только пользователь (владелец проекта).**

Агент и субагенты **не выполняют** без отдельного явного разрешения на конкретное действие:

- `git commit`, `git commit --amend`;
- `git push`, `git push --force`, `git push --tags`;
- `gh pr create`, `gh pr merge`, `gh release create`;
- `git tag`, создание и удаление веток в удалённом репозитории;
- любые операции, меняющие историю (`rebase`, `reset --hard`, `filter-branch`).

Разрешено без разрешения:

- `git status`, `git diff`, `git log`, `git show`, `git branch --list`;
- `git add` **не** выполнять: индексацию и коммит делает пользователь.

Порядок завершения задачи:

1. Внести изменения в файлы.
2. Запустить проверки (lint, typecheck, tests, build — что применимо).
3. Показать пользователю список изменённых файлов, `git diff --stat` и результат проверок.
4. Предложить текст сообщения коммита, но **не коммитить**.
5. Дождаться, пока пользователь сам закоммитит и запушит.

Если пользователь явно просит «закоммить» или «запушь» — это разрешение действует
только на этот один раз и только на названные действия.

## Стек

- Next.js 16 App Router, React 19, TypeScript strict
- Tailwind CSS 4
- Prisma 7 + PostgreSQL 16
- Zod
- Vitest + Playwright
- CI: GitHub Actions (`.github/workflows/ci.yml`)

## Обязательные проверки перед сдачей задачи

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Если задача затрагивает БД — дополнительно применить миграции на тестовой БД и
прогнать e2e. Если проверка недоступна, сказать почему.

## Продуктовые правила

- Интерфейс — по-русски: «тест», «баллы», «освоено», «уровень знатока»,
  «Мои результаты». Не использовать в UI: «XP», «mastery», «streak», «лидерборд», «квиз».
- Аудитория 45+, ядро 55+: крупный текст, высокий контраст, кнопки ≥ 56 px,
  без таймеров, автопереходов и звуков по умолчанию.
- Проверка ответов, баллы и прогресс — только на сервере. Правильные ответы
  не отдаются клиенту до ответа.
- Мутации идемпотентны, ошибки в едином формате, без публичных рейтингов.
- Не логировать пароли, токены, хеши и email. Не коммитить секреты.
