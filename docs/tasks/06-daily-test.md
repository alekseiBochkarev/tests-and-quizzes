## 1. Зачем

«Тест дня» даёт понятную причину возвращаться каждый день: короткий набор из
разных тем, который проходится за несколько минут. Это привычка, а не
соревнование:

- 5–7 вопросов из разных тем;
- один набор в день, сброс в 00:00 по Москве;
- +30 баллов за завершение и участие в общей серии дней;
- отдельная крупная карточка на главной;
- без таймера, без соревнования по скорости и без наказания за пропуск.

---

## 2. Продуктовые решения

| Вопрос | Решение |
|---|---|
| Размер набора | До 7 вопросов; минимум 5, иначе тест дня недоступен |
| Темы | Сначала по одному вопросу из каждой темы, при нехватке тем — вторые вопросы |
| Набор | Один и тот же для всех пользователей в московскую дату |
| Персонализация | Отложена до v1.1 вместе с рекомендациями v2 |
| Попыток в день | Одна; повторный старт возвращает ту же попытку |
| Прерывание | Попытка становится `ABANDONED`; ответы и баллы за них сохраняются |
| Бонус | +30 баллов за завершение, один раз |
| Серия | Завершённый тест дня считается активным днём, как обычная попытка |
| Пропуск | Ничего не блокирует и не штрафует; серия начнётся заново |
| Дата | `Attempt.dailyDate` — московская дата, `DATE` в UTC-полночь |

## 3. Модель данных

В `AttemptMode` добавлено значение `DAILY`. В `Attempt` — nullable-поле и
уникальный индекс:

```prisma
enum AttemptMode {
  TRAINING
  REVIEW
  DAILY
}

model Attempt {
  // …
  mode      AttemptMode @default(TRAINING)
  dailyDate DateTime?   @db.Date

  @@unique([userId, dailyDate])
}
```

У обычных тренировок и повторений `dailyDate = NULL`. PostgreSQL не считает
`NULL` равными, поэтому уникальный индекс не мешает создавать много попыток без
даты. Для «Теста дня» индекс гарантирует одну попытку на пользователя в день,
даже при параллельных запросах.

### 3.1. Миграция

```sql
ALTER TYPE "AttemptMode" ADD VALUE 'DAILY';
ALTER TABLE "Attempt" ADD COLUMN "dailyDate" DATE;
CREATE UNIQUE INDEX "Attempt_userId_dailyDate_key" ON "Attempt"("userId", "dailyDate");
```

Существующие попытки не меняются. Миграция применяется на пустой и заполненной
базе.

### 3.2. План отката

Быстрый безопасный откат — скрыть карточку и маршрут, оставив историю:

```sql
DROP INDEX "Attempt_userId_dailyDate_key";
ALTER TABLE "Attempt" DROP COLUMN "dailyDate";
```

Значение `DAILY` в enum остаётся, но нигде не создаётся. Полное удаление
значения требует пересоздания типа `AttemptMode`; перед этим существующие
попытки нужно перевести в `TRAINING`:

```sql
UPDATE "Attempt" SET mode = 'TRAINING' WHERE mode = 'DAILY';
ALTER TABLE "Attempt" ALTER COLUMN mode DROP DEFAULT;
ALTER TYPE "AttemptMode" RENAME TO "AttemptMode_old";
CREATE TYPE "AttemptMode" AS ENUM ('TRAINING', 'REVIEW');
ALTER TABLE "Attempt" ALTER COLUMN mode TYPE "AttemptMode" USING mode::text::"AttemptMode";
ALTER TABLE "Attempt" ALTER COLUMN mode SET DEFAULT 'TRAINING';
DROP TYPE "AttemptMode_old";
```

Попытки и весь учебный прогресс сохраняются; теряется только привязка к дате
«Теста дня».

## 4. Серверные правила

Код: `lib/daily/rules.ts` и `lib/daily/service.ts`.

- **Дата.** `dailyDateKey(now)` считает дату в `Europe/Moscow`. В 00:00 МСК
  доступен новый набор; до этого повторный старт возвращает сегодняшнюю попытку.
- **Набор.** Кандидаты — только опубликованные вопросы опубликованных тем.
  Выбор детерминирован по дате: порядок тем и вопросов задаётся стабильным
  хешем `дата + id`. Один вопрос из темы, затем второй круг, если тем меньше 7.
- **Минимум.** Если набралось меньше 5 вопросов, старт возвращает
  `daily_unavailable` (409). Карточка на главной остаётся, но попытка не
  создаётся.
- **Идемпотентность.** Перед созданием ищется попытка по `(userId, dailyDate)`.
  Если она есть, возвращается она же: `in_progress`, `completed` или
  `abandoned`. Параллельный старт защищён уникальным индексом: проигравший
  запрос получает уже созданную попытку.
- **Незавершённый прошлый день.** При старте нового дня незавершённые
  `DAILY`-попытки прошлых дат помечаются `ABANDONED`. На новый день они не
  переносятся; данные ответы и баллы за них сохраняются.
- **Бонус.** При завершении `DAILY`-попытки к обычным баллам за завершение
  добавляется `DAILY_BONUS_XP = 30`. Повторный `finish` идемпотентен и бонус
  второй раз не начисляет. При прерывании бонуса нет, баллы за ответы остаются.
- **Серия.** Завершение любой попытки, включая «Тест дня», обновляет
  `dailyStreak` по локальной дате пользователя. Пропуск дня сбрасывает серию в 1
  при следующей активности, без штрафа.
- **Прогресс.** Это обычная `Attempt`: `QuestionProgress`, `TopicProgress`,
  `DailyActivity` и история обновляются теми же функциями, что у тренировки.
  Отдельной статистики «теста дня» нет.
- **Безопасность.** Правильные ответы не отдаются до ответа; проверка только на
  сервере; старт защищён сессией, same-origin и rate-limit старта попыток.

## 5. API

`POST /api/v1/daily/start` — без тела запроса.

Ответ `201` при создании и `200`, если попытка уже была:

```json
{
  "data": {
    "attemptId": "…",
    "questionCount": 7,
    "status": "in_progress",
    "created": true
  }
}
```

`status`: `in_progress`, `completed`, `abandoned`. `created` помогает отличить
создание от повторного запроса, но клиенту достаточно `attemptId` и `status`.

Ошибки — в общем формате:

| Код | HTTP | Когда |
|---|---|---|
| `unauthorized` | 401 | Нет сессии |
| `daily_unavailable` | 409 | Меньше 5 опубликованных вопросов |
| `rate_limited` | 429 | Слишком частые старты |

Дальше клиент работает с обычными маршрутами попытки:
`/attempts/[id]`, `/api/v1/attempts/[id]/answers`,
`/api/v1/attempts/[id]/finish`, `/api/v1/attempts/[id]/abandon`.

## 6. Интерфейс

- `app/page.tsx` — секция «Тест дня» сразу после блока прогресса, крупная
  карточка с рамкой акцента.
- `components/daily/DailyTestCard.tsx` — четыре состояния:
  - **Доступен:** описание, +30 баллов и кнопка «Начать тест дня»;
  - **Идёт:** «Продолжить тест дня»;
  - **Пройден:** результат «X из Y верно» и ссылка на разбор;
  - **Прерван:** честное сообщение, что ответы сохранены.
- `components/attempts/AttemptPlayer.tsx` — заголовок «Тест дня».
- `app/attempts/[id]/result/page.tsx` — заголовок «Тест дня завершён» /
  «Тест дня прерван» и пояснение про +30 баллов.
- `lib/stats/service.ts` — «Тест дня» в «Продолжить» и истории «Мои результаты».

Тексты — по-русски, без слов «XP», «mastery», «streak», «квиз». Кнопки ≥ 56 px,
крупный текст, без таймера и автопереходов.

- [x] Каждый день доступен один набор из 5–7 вопросов из разных тем.
- [x] Набор сбрасывается в 00:00 по Москве.
- [x] Повторный старт возвращает ту же попытку и не создаёт дубль.
- [x] Завершение даёт +30 баллов один раз и учитывается в серии.
- [x] Пропуск дня не блокирует и не штрафует пользователя.
- [x] Результат — обычная попытка: прогресс, история и mastery работают.
- [x] На главной есть отдельная карточка «Тест дня» со всеми состояниями.
- [x] Гость не видит карточку: она часть личного кабинета.
- [x] Старые тренировки, выпуски и прогресс не ломаются.
- [x] Правильные ответы не отдаются до ответа; проверка только на сервере.
- [x] Интерфейс соответствует требованиям аудитории 45+/55+.

## 9. Ограничения

- Набор общий для всех и не подстраивается под интересы и слабые темы.
- Одна попытка в день: прерванный тест нельзя начать заново в тот же день.
- Незавершённый вчерашний набор не переносится на новый день и закрывается как
  прерванный.
- Нет отдельной статистики «сколько тестов дня пройдено» и календаря привычки.
- Письма-напоминания о тесте дня — задача GRW-04.
