## 1. Зачем

ТЗ требует два базовых права пользователя (AUTH-6, LEG-4, LEG-5):

- удалить аккаунт, не потеряв при этом честно заработанную статистику;
- получить копию своих данных в машиночитаемом виде.

До задачи удаления и выгрузки не было вообще: человек мог только выйти из
аккаунта. Это юридический блокер перед публичным запуском и одновременно
понятная функция «забрать свои данные».

Задача закрывает:

- самостоятельный экспорт профиля, согласий, попыток, ответов и прогресса;
- выгрузку истории тренировок в CSV для Excel;
- самостоятельное удаление аккаунта с подтверждением паролем;
- обезличивание персональных данных с сохранением агрегированной статистики;
- запись удаления в журнал `AuditLog`.

## 2. Продуктовые решения

| Вопрос | Решение |
|---|---|
| Удаление — физическое или анонимизация | Анонимизация: ПДн стираются, агрегаты остаются (§9.4) |
| Где кнопка удаления | На `/account` в блоке «Данные и аккаунт» |
| Где подтверждение | Отдельная страница `/account/delete`, не модальное окно |
| Барьеры удаления | Текущий пароль + слово `УДАЛИТЬ` + чекбокс понимания |
| Регистр слова | Не важен; пробелы по краям обрезаются |
| Почему не только пароль | Слово заставляет прочитать последствия, а не нажать «да» рефлекторно |
| Что после удаления | Редирект на `/?account=deleted` с сообщением; сессия очищена |
| Восстановление | Невозможно — сказано прямо на странице и в чекбоксе |
| Экспорт | JSON — всё; CSV — история тренировок |
| Формат CSV | UTF-8 с BOM, разделитель `;`, переводы строк CRLF |
| Почему BOM и `;` | Excel в русской локали иначе ломает кириллицу и колонки |
| Rate-limit удаления | 5 попыток в час на пользователя |
| Пароль в экспорте | Не попадает никогда, включая хеш |
| Аудит | `AuditLog` без IP, User-Agent и email |

Интерфейс не использует тёмных паттернов: рядом с destructive-кнопкой
объяснено, что произойдёт, и предложено сначала скачать данные.

## 3. Модель данных

### 3.1. Анонимизация

Пользователь остаётся строкой в `User`, потому что на него ссылаются попытки,
ответы и прогресс. Меняются только персональные поля:

| Поле | После удаления |
|---|---|
| `email` / `emailNormalized` | `deleted-<id>@deleted.invalid` |
| `passwordHash` | `null` |
| `name`, `avatarUrl` | `null` |
| `emailVerifiedAt`, `interestsSetAt` | `null` |
| `lastLoginAt`, `lockedUntil` | `null` |
| `failedLoginCount` | `0` |
| `role` | `USER` |
| `deletedAt` | момент удаления |
| `sessionEpoch` | `+1` — все сессии становятся недействительными |

Домен `deleted.invalid` зарезервирован стандартом (RFC 2606) и не может быть
настоящим адресом. Суффикс `userId` уникален, поэтому повторное удаление и
параллельные запросы не сталкиваются на unique-индексе.

### 3.2. Что удаляется полностью

- `AuthIdentity` — внешние идентификаторы входа;
- `EmailToken` — ссылки подтверждения и сброса пароля;
- `UserInterest` — персональные предпочтения.

### 3.3. Что остаётся

- `Attempt`, `Answer` — история прохождений;
- `QuestionProgress`, `TopicProgress` — прогресс;
- `UserStats`, `DailyActivity` — агрегированная статистика;
- `Consent` — сами согласия сохраняются как доказательство их выдачи,
  но `ip` и `userAgent` обнуляются.

Связать оставшиеся записи с человеком по email, имени или устройству нельзя.

### 3.4. Аудит

Новая таблица `AuditLog`:

```prisma
model AuditLog {
  id          String   @id @default(cuid())
  actorUserId String?
  action      String
  entityType  String?
  entityId    String?
  createdAt   DateTime @default(now())

  actor User? @relation(fields: [actorUserId], references: [id], onDelete: SetNull)
}
```

Индексы: `(actorUserId, createdAt)`, `(entityType, entityId)`,
`(action, createdAt)`.

Запись при удалении: `action = "account.deleted"`, `entityType = "User"`,
`entityId = userId`. Персональных данных в журнале нет: только действие,
субъект и время. `actorUserId` при удалении самого пользователя сохраняет id —
это обезличенная строка, но она нужна, чтобы связать событие с объектом.

`AuditLog` введён здесь минимально. **CNT-05 расширяет его событиями
редакционного workflow, а не создаёт таблицу заново.**

## 4. API

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/v1/me/export` | Полный экспорт JSON |
| `GET` | `/api/v1/me/export?format=csv` | История тренировок CSV |
| `DELETE` | `/api/v1/me` | Удаление (анонимизация) аккаунта |

### 4.1. Экспорт

Требует сессию. Ответ всегда `Cache-Control: no-store, private` и
`Content-Disposition: attachment`.

JSON содержит:

- `format: "testy-account-export"`, `version: 1`, `exportedAt`;
- `profile` — id, email, имя, роль, часовой пояс, даты;
- `consents` — тип, версия, принято/нет, IP, User-Agent, дата;
- `interests` — тема, вес, источник;
- `attempts` — режим, статус, счёт, баллы, время, тема/выпуск и все ответы;
- `questionProgress` — освоение по вопросам;
- `topicProgress` — прогресс по темам;
- `stats` — баллы, уровень, серия, точность;
- `dailyActivity` — активность по дням.

Все даты — ISO 8601. Пароль и его хеш не выбираются из БД вообще.

CSV: заголовок «Дата;Тема;Формат;Статус;Вопросов;Отвечено;Верно;Баллы;Длительность, мин»,
подписи режимов и статусов по-русски, дата в часовом поясе пользователя.

### 4.2. Удаление

Тело:

```json
{ "password": "…", "confirmation": "УДАЛИТЬ" }
```

Успех — `204 No Content`, cookie сессии очищается.

Правила:

- same-origin обязателен;
- тело — JSON до 32 КБ;
- rate-limit: 5 попыток в час на пользователя;
- пароль проверяется по хешу; неверный пароль — `400` с ошибкой поля;
- слово `УДАЛИТЬ` проверяется без учёта регистра и пробелов по краям;
- проверяется, что сессия не устарела (`sessionEpoch` совпадает) и аккаунт
  ещё не удалён;
- вся анонимизация выполняется в одной транзакции вместе с записью аудита;
- ошибки — в общем формате `{ error: { code, message, details? } }`, ответ
  `no-store`.

## 5. Интерфейс

| Место | Что видит пользователь |
|---|---|
| `/account` | Блок «Данные и аккаунт»: выгрузка JSON, история CSV, ссылка на удаление |
| `/account/delete` | Объяснение последствий, пароль, слово `УДАЛИТЬ`, чекбокс, кнопка «Удалить аккаунт навсегда» |
| `/account/delete` | Ссылки «скачать данные» и «вернуться» — уйти без удаления так же просто |
| `/` после удаления | Сообщение «Аккаунт удалён» |
| `/legal/privacy` | Сроки хранения, анонимизация и ссылка на `/account` |

Решения для аудитории 55+:

- отдельная страница вместо модального окна: ничего не перекрывает контент;
- последствия перечислены списком, а не спрятаны в мелкий текст;
- destructive-кнопка красная, но не мигает и не двигается;
- ошибки показываются текстом с `role="alert"` и привязаны к полям;
- подсказка объясняет, зачем нужен пароль и почему регистр слова не важен;
- кнопки не ниже 56 px, текст крупный, фокус видимый.

- формат, версия и время выгрузки;

## 9. Ограничения

- Удаление — анонимизация, а не физическое стирание строк. Так требует §9.4:
  агрегированная статистика остаётся. Полное удаление по запросу — ручная
  процедура администратора.
- Экспорт собирает всю историю пользователя одним ответом. Для объёмов
  реального человека этого достаточно; пагинация не нужна.
- CSV содержит только историю тренировок. Профиль, согласия и прогресс —
  в JSON.
- В `AuditLog` пока одно событие — `account.deleted`. Остальные действия
  добавятся в CNT-05.
- Нет экрана истории удалений и восстановления: восстановление невозможно
  по замыслу.
- Rate-limit в памяти процесса; при горизонтальном масштабировании переедет
  в Redis вместе с остальными бакетами.
- Экспорт не архивируется (ZIP): браузер скачивает один файл.
