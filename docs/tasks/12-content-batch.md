## 1. Зачем

До этой задачи каталог наполнялся демо-набором: 122 вопроса, почти все
с `Question.isDemo = true`. Для прогресса и трёх–пяти сессий по теме этого мало,
а по ТЗ §7.5 для MVP нужно **8 тем × 60 вопросов = 480 вопросов**.

Импорт (CNT-01) и админка (CNT-04) уже готовы. Не хватает самого контента:
вопросов с вариантами, правильными ответами и объяснениями.

В `forms_writer` готовой партии нет: файлы состояния хранят только тексты уже
заданных вопросов (около 1600) без вариантов и ответов. Поэтому партия пишется
заново в формате `forms_writer`, а не выгружается из состояния.

## 3. Формат партии

Файлы лежат в `content/batches/` и совпадают с форматом `forms_writer`:

```json
{
  "questions": [
    {
      "topic": "Советское кино",
      "question": "Кто режиссёр фильма «Служебный роман»?",
      "options": ["Георгий Данелия", "Леонид Гайдай", "Владимир Меньшов", "Эльдар Рязанов"],
      "correct_index": 3,
      "explanation": "«Служебный роман» снял Эльдар Рязанов в 1977 году. Главные роли сыграли Андрей Мягков и Алиса Фрейндлих."
    }
  ]
}
```

Правила:

- тема — строго ключ из `topic-map.json`;
- ровно 4 варианта, все непустые и разные;
- `correct_index` — целое число от 0 до 3;
- объяснение обязательно, 1–3 предложения: оно показывается после ответа;
- `context` можно не заполнять: в БД он пока не хранится;
- правильные ответы разносятся по всем четырём позициям, чтобы ответ нельзя
  было угадать по месту в списке;
- факты — только проверяемые, без политики, религии, медицинских советов
  и современной поп-культуры (ТЗ §7.3);
- без отрицательных формулировок, двусмысленностей и варианта
  «все вышеперечисленное»;
- варианты сопоставимы по длине и правдоподобны.

## 5. Импорт

Перед импортом поднять БД (`npm run db:up`) и применить миграции.

```powershell
# 1. Проверить план без записи
npm run db:import -- --file content/batches/cinema-01.json --dry-run

# 2. Залить атомарно: при любой ошибке партия откатится
npm run db:import -- --file content/batches/cinema-01.json --strict

# 3. Сохранить отчёт для редакции
npm run db:import -- --file content/batches/cinema-01.json --report logs/cinema-import.json
```

Что произойдёт:

- 60 вопросов создадутся с `isDemo = false`, `status = PUBLISHED`;
- восемь демо-вопросов темы `soviet-cinema` уйдут в `ARCHIVED`;
- `TopicProgress` пересчитается у пользователей, у которых он уже есть.

Повторный импорт ничего не создаст: все вопросы найдутся по `contentHash`.

### Что будет с демо-выпуском

Демо-выпуск `release-1` темы «Советское кино» собран из демо-вопросов. После
их архивации в нём остаётся меньше 10 играбельных вопросов, поэтому
`getTopicQuizzes` перестанет показывать выпуск. Это ожидаемо: реальные выпуски
(по ТЗ — 3 на тему) собираются из новой партии отдельным шагом. До этого тема
остаётся доступной для обычных тренировок на 10/15/20/30 вопросов.

Это же произойдёт с любой темой, куда заливается реальный контент. Планируя
волну, выпуски лучше готовить сразу после импорта темы.

## 6. Откат

Миграции нет. Если партия окажется неудачной:

1. перевести созданные вопросы в `ARCHIVED` (админка или SQL по `contentHash`);
2. вернуть демо-вопросы в `PUBLISHED`, если нужно снова показать демо;
3. пересчитать `TopicProgress` тем же скриптом импорта с `--dry-run` нельзя —
   пересчёт делает только запись; проще повторить импорт исправленной партии.

Физическое удаление вопросов нежелательно: на них могут ссылаться ответы
пользователей.
