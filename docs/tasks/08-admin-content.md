# CNT-04. CRUD тем и вопросов с импортом в админке

> **ID:** `CNT-04`
>
> **Статус:** реализовано 24.11.2026. Миграции не нужны: `ContentStatus`,
> `Question.version` и `Question.contentHash` уже есть в схеме.
>
> **Поток:** B. CONTENT. Зависит от CNT-01 (импорт) и CNT-03 (админ-каркас).
> Совместимо с A, C, D, E, F.

---

## 1. Зачем

CNT-03 дала защищённый `/admin`, но разделы «Темы и вопросы» и «Импорт» были
заглушками: контент менялся только сидом и CLI. Редактор не мог создать тему,
исправить формулировку, опубликовать вопрос или загрузить свежую партию JSON
без терминала.

CNT-04 закрывает этот разрыв:

- темы создаются, редактируются, публикуются и убираются в архив;
- вопросы создаются, редактируются, публикуются и архивируются;
- импорт `forms_writer` идёт в выбранную тему с обязательным предпросмотром;
- проверка ответов и прогресс остаются серверными, публичный API каталога не
  меняется.

---

## 2. Продуктовые решения

| Вопрос | Решение |
|---|---|
| Удаление темы или вопроса | Не физическое: перевод в `ARCHIVED` |
| Почему | На вопрос ссылаются попытки, ответы и прогресс |
| Редактирование опубликованного вопроса | Изменение текста, вариантов или правильного ответа создаёт новую версию |
| Что не создаёт новую версию | Объяснение, сложность, изображение |
| Импорт | Всегда в выбранную тему, поле `topic` файла только для отчёта |
| Предпросмотр | Обязателен; запись только после подтверждения |
| Лимит импорта | 500 вопросов и 1 МБ тела запроса |
| Черновик без объяснения | Разрешён; публикация без объяснения запрещена |
| Кто может менять контент | `EDITOR` и `ADMIN` |
| Аудит действий | Не входит; остаётся за CNT-05 |

Обычный пользователь не должен знать о служебных API: гость получает `401`,
`USER` — `404`. Ответы API используют общий конверт `{ data }` /
`{ error, requestId }`.

## 3. Модель контента

### 3.1. Статусы

`ContentStatus` уже был в схеме:

- `DRAFT` — виден только в админке;
- `PUBLISHED` — участвует в тренировках и каталоге;
- `ARCHIVED` — скрыт, но история и прогресс сохраняются.

Тема появляется в публичном каталоге только если она `PUBLISHED` и содержит
хотя бы один опубликованный вопрос. Это поведение существующего
`lib/content/catalog.ts` не менялось.

### 3.2. Версионирование вопроса

`questionContentChanged` сравнивает текст, варианты и правильный ответ.
Если опубликованный вопрос меняется по этим полям:

1. старая запись переводится в `ARCHIVED`;
2. создаётся новая запись с `version = старая версия + 1`;
3. пересчитывается `TopicProgress`.

Объяснение, сложность, `imageUrl` и `imageLicense` обновляются на месте: они
уточняют вопрос и не ломают привязку прогресса. Черновик редактируется на
месте; номер версии растёт, но архивная копия не создаётся.

### 3.3. Демо-контент

После появления реального опубликованного вопроса демо-вопросы темы
архивируются. Логика повторяет CLI-импорт CNT-01 и выполняется в той же
транзакции.

### 3.4. Прогресс

После создания, публикации, архивации и импорта вызывается существующий
`computeTopicAggregate`. Он пересчитывает `TopicProgress` пользователей темы,
поэтому `totalQuestions` не расходится с числом опубликованных вопросов.

## 4. API

Все маршруты живут в `/api/v1/admin/*`, требуют staff-роль, same-origin и
rate-limit. Тело читается общим `readJsonBody`: 32 КБ для CRUD, 1 МБ для
импорта.

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/api/v1/admin/topics` | Создать тему |
| `PATCH` | `/api/v1/admin/topics/[id]` | Изменить тему |
| `DELETE` | `/api/v1/admin/topics/[id]` | Убрать тему в архив |
| `POST` | `/api/v1/admin/topics/[id]/questions` | Добавить вопрос |
| `PATCH` | `/api/v1/admin/questions/[id]` | Изменить вопрос |
| `DELETE` | `/api/v1/admin/questions/[id]` | Убрать вопрос в архив |
| `POST` | `/api/v1/admin/import/preview` | Разобрать файл и вернуть план |
| `POST` | `/api/v1/admin/import/apply` | Применить проверенный файл |

Коды ошибок:

- `validation_error` — `details.fields` для подсветки полей;
- `slug_taken` — адрес темы занят;
- `duplicate_question` — такой вопрос уже есть в теме;
- `unknown_topic`, `unknown_question`, `unknown_category`;
- `import_has_errors` — в файле есть ошибки, импорт не применён;
- `import_too_large`, `import_empty`;
- `origin_mismatch`, `rate_limited`, `unauthorized`, `not_found`.

Ошибки БД и непредвиденные исключения не раскрывают stack trace: общий
`handleRouteError` возвращает `503` или `500` с requestId.

Rate-limit (in-memory, как остальной проект):

- CRUD — 240 действий в час на сотрудника;
- импорт — 60 вызовов в час на сотрудника.

## 5. Интерфейс

| Маршрут | Содержимое |
|---|---|
| `/admin/topics` | Темы по разделам, статусы, количество вопросов, переход к теме |
| `/admin/topics/new` | Создание темы |
| `/admin/topics/[id]` | Карточка темы, вопросы, фильтр по статусу, архивация |
| `/admin/topics/[id]/edit` | Редактирование темы |
| `/admin/topics/[id]/questions/new` | Создание вопроса |
| `/admin/questions/[id]` | Редактирование вопроса, архивация |
| `/admin/import` | Выбор темы, файл/JSON, предпросмотр, подтверждение |

Решения интерфейса:

- адрес темы подставляется из русского названия (`slugify`), редактору не нужно
  знать латиницу;
- после сохранения показывается понятное подтверждение, а после версионирования
  — отдельное сообщение о новой версии;
- архив требует подтверждения и объясняет, что прогресс сохранится;
- фильтр вопросов по статусу доступен ссылками и не требует JavaScript;
- ошибки полей показываются рядом с полем, общая ошибка — в `Alert`;
- кнопки не ниже 56 px, крупный текст, статус обозначен и цветом, и подписью.

Импорт:

1. выбрать тему;
2. загрузить `.json` или вставить текст;
3. нажать «Проверить и показать предпросмотр»;
4. увидеть «добавится / обновится / новых версий / пропустится / черновиков /
   ошибок / предупреждений / демо в архив»;
5. подтвердить кнопкой «Загрузить вопросы».

Любое изменение файла, текста или темы сбрасывает предпросмотр: применить
устаревший план нельзя.

## 6. Импорт JSON

Поддерживается формат `forms_writer`:

```json
{
  "questions": [
    {
      "topic": "История",
      "question": "В каком году пала Западная Римская империя?",
      "options": ["395", "410", "476", "1453"],
      "correct_index": 2,
      "explanation": "В 476 году Одоакр низложил Ромула Августула."
    }
  ]
}
```

Правила:

- `topic` может отсутствовать: вопросы попадут в выбранную тему;
- если `topic` указан, он не создаёт новые темы и не меняет выбранную;
- вопрос без объяснения сохраняется как `DRAFT`;
- дубликат внутри файла пропускается с предупреждением;
- совпадение по `contentHash` обновляет объяснение и статус;
- тот же текст с другими вариантами или ответом создаёт новую версию;
- архивный вопрос не возвращается в публикацию автоматически;
- ошибки блокируют применение целиком.

Предпросмотр и применение считают план заново. Если между ними контент
изменился, применится актуальное состояние базы, а не устаревший снимок.

- [x] Прогресс темы пересчитывается после публикации, архивации и импорта.

## 10. Ограничения

- Физического удаления нет — это осознанно.
- Нет массовых операций (публикация/архивация пачкой) — ADM-7.
- Нет журнала действий и истории правок с автором — CNT-05.
- Нет загрузки изображений в хранилище: только `imageUrl` и подпись.
- Нет тонких прав «редактор только своей темы»: роль действует на всю админку.
- Управление выпусками (`Quiz`) и аналитика остаются заглушками.
- Импорт не создаёт темы: тема выбирается в интерфейсе.
- Rate-limit in-memory: при нескольких инстансах нужен общий счётчик.

## 11. Откат

Миграции нет. Откат — удалить код CNT-04 и вернуть заглушки:

1. удалить `app/api/v1/admin/*`, страницы `app/admin/topics/*` и
   `app/admin/questions/*`;
2. вернуть заглушки `app/admin/topics/page.tsx` и `app/admin/import/page.tsx`;
3. удалить `components/admin/*Form.tsx`, `ArchiveButton`, `AdminStatusBadge`,
   `lib/admin/client.ts`, `content.ts`, `importPlan.ts`, `schemas.ts`,
   `contentRules.ts`, `slug.ts`, `errors.ts`, `api.ts`;
4. удалить `tests/unit/admin/*` и `tests/e2e/admin-content.spec.ts`.

Данные, созданные через админку, остаются в базе. При необходимости их можно
вернуть в исходное состояние сидом и импортом. Пользователи, попытки и прогресс
не затрагиваются.
