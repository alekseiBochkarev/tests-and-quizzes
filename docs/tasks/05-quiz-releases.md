## 1. Зачем

Тренировка уже даёт понятный финиш, но у пользователя нет привычного формата
«тест на 10–12 вопросов», который можно открыть по ссылке и пройти целиком.
Готовый выпуск закрывает этот сценарий:

- на странице темы появляется блок «Готовые выпуски»;
- выпуск живёт по постоянной ссылке `/tests/[тема]/[выпуск]`;
- прохождение и результат — обычная попытка, поэтому прогресс, баллы и история
  работают без отдельного контура.

---

## 2. Продуктовые решения

| Вопрос | Решение |
|---|---|
| Названия | Тематическое название, например «История: основной выпуск». Если названия нет — «Выпуск N» |
| Сколько выпусков | Один выпуск на тему; несколько выпусков — позже, вместе с админкой |
| Мало вопросов | Если опубликованных вопросов меньше 10, выпуск не показывается |
| Длина | 10–12 вопросов; в сиде — 10 |
| Доступ | Страница выпуска открыта всем, старт требует входа |
| Прогресс | Выпуск — обычная `Attempt` с `quizId`; отдельной статистики выпусков нет |
| Порядок | Фиксированный `QuizQuestion.order`; случайной выдачи нет |

## 3. Модель данных

Добавлены две таблицы и nullable-поле:

```prisma
model Quiz {
  id          String        @id @default(cuid())
  topicId     String
  slug        String
  title       String
  description String?
  status      ContentStatus @default(PUBLISHED)
  isDemo      Boolean       @default(false)
  createdAt   DateTime      @default(now())
  updatedAt   DateTime      @updatedAt

  topic     Topic          @relation(fields: [topicId], references: [id], onDelete: Restrict)
  questions QuizQuestion[]
  attempts  Attempt[]

  @@unique([topicId, slug])
  @@index([topicId, status])
}

model QuizQuestion {
  id         String @id @default(cuid())
  quizId     String
  questionId String
  order      Int

  quiz     Quiz     @relation(fields: [quizId], references: [id], onDelete: Cascade)
  question Question @relation(fields: [questionId], references: [id], onDelete: Restrict)

  @@unique([quizId, questionId])
  @@unique([quizId, order])
  @@index([questionId])
}
```

В `Attempt` добавлено `quizId String?` и связь `quiz Quiz?` с
`onDelete: SetNull`: удаление выпуска не удаляет историю попыток.

Миграция только добавляет таблицы, индексы и nullable-колонку. Существующие
попытки получают `quizId = NULL` и продолжают работать как раньше.

### 3.1. План отката

Если фичу нужно убрать до появления реальных выпусков:

```sql
ALTER TABLE "Attempt" DROP CONSTRAINT "Attempt_quizId_fkey";
DROP INDEX "Attempt_quizId_idx";
ALTER TABLE "Attempt" DROP COLUMN "quizId";
DROP TABLE "QuizQuestion";
DROP TABLE "Quiz";
```

Попытки и весь учебный прогресс сохраняются; теряется только привязка к выпускам
и их составы.

## 4. Серверные правила

Код: `lib/quizzes/rules.ts` и `lib/quizzes/service.ts`.

- Выпуск виден, только если он `PUBLISHED`, тема `PUBLISHED`, а в наборе 10–12
  опубликованных вопросов **этой же темы**.
- Архивные и черновые вопросы, вопросы из другой темы и дубликаты отбрасываются.
- Состав пересчитывается при каждом чтении. Если импорт заархивировал вопросы и
  осталось меньше 10, выпуск исчезает из темы, а прямой старт возвращает
  `quiz_unavailable`.
- `createAttempt` при `quizId` требует `mode = TRAINING` и не принимает
  `topicId`/`categoryId` одновременно (ошибка `invalid_scope`).
- При старте сервер заново загружает вопросы в порядке `QuizQuestion.order`,
  создаёт `Attempt` с `quizId` и `topicId` и обычный снимок `AttemptAnswer`.
- Вопросы не дублируются: `(quizId, questionId)` и `(attemptId, questionId)`
  уникальны. Повторный ответ и повторный `finish` идемпотентны, как у тренировки.

Коды ошибок: `quiz_not_found` (404), `quiz_unavailable` (409),
`invalid_scope` (400).

## 5. API

`POST /api/v1/attempts` принимает либо тренировку, либо выпуск:

```json
{ "quizId": "…", "mode": "TRAINING" }
```

```json
{ "topicId": "…", "count": 10, "mode": "TRAINING" }
```

`count` для выпуска не передаётся и не влияет на набор. Ответ прежний:
`{ "data": { "attemptId", "questionCount", "mode" } }`.

Правильные ответы по-прежнему не отдаются до ответа пользователя.

## 6. Интерфейс

- `app/tests/[slug]/page.tsx` — блок «Готовые выпуски» с названием, описанием,
  числом вопросов и кнопкой «Открыть выпуск».
- `app/tests/[slug]/[quizSlug]/page.tsx` — постоянная ссылка, хлебные крошки,
  описание и запуск.
- `components/content/StartQuiz.tsx` — запуск выпуска; гость уходит на вход и
  возвращается на ту же ссылку.
- `components/attempts/AttemptPlayer.tsx` — в заголовке название выпуска.
- `app/attempts/[id]/result/page.tsx` — подпись «Выпуск «…»».
- `lib/stats/service.ts` — выпуск отображается в «Продолжить» и истории
  «Мои результаты».

Все тексты — по-русски, кнопки ≥ 56 px, без таймера и автопереходов. Слова
«квиз», «XP», «mastery», «streak» в интерфейсе не используются.

## 7. Сид и демо-контент

`scripts/seed.mjs` для темы с ≥ 10 вопросами создаёт один выпуск:

- `id = seed-quiz-<topic>`, `slug = release-1`, `isDemo = true`;
- название `<Тема>: основной выпуск`;
- состав — первые 10 вопросов темы;
- повторный сид пересобирает состав и метаданные этого выпуска, но не
  перезаписывает `Quiz.status`.

Сейчас демо-выпуски есть у тем «Гарри Поттер», «Картины и художники»,
«Животные», «История». У тем с 8–9 вопросами выпуска нет.

Если импорт `forms_writer` архивирует демо-вопросы, выпуск автоматически
перестаёт быть полным и скрывается; повторный сид не возвращает архивные вопросы
в публикацию.

## 9. Критерии приёмки

- [x] Выпуск — именованный набор 10–12 вопросов внутри темы.
- [x] Выпуск открывается из каталога и имеет постоянную ссылку.
- [x] Результат сохраняется как обычная попытка.
- [x] Вопросы не дублируются в одной попытке.
- [x] Старые тренировки и прогресс не ломаются.
- [x] Гость видит выпуск, но для старта входит в аккаунт.
- [x] Если вопросов меньше 10, выпуск не показывается.

---

## 10. Ограничения

- Один выпуск на тему и только демо-составы из сида; управления через админку
  нет.
- Отдельной статистики «выпуск пройден / не пройден» нет: история и прогресс
  общие с тренировками.
- Импорт `forms_writer` не создаёт выпуски автоматически — это следующий шаг
  после появления админки.
