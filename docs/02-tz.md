## TL;DR

1. **Аудитория:** по статистике тестов в Дзене ~74% зрителей старше 45 лет, ядро — 55+. Проектируем под взрослую аудиторию, а не адаптируем молодёжный квиз.
2. **Продукт:** спокойный сайт тематических тестов (10–30 вопросов) с личным прогрессом, повторением ошибок, «тестом дня», дипломом и шарингом результата.
3. **Модель:** выпуск (в UI — «тест») — единица потребления, вопрос — единица прогресса, тема — единица долгосрочной мотивации.
4. **Прогресс:** освоение 0–5 по каждому вопросу → прогресс темы `охват × качество` → баллы/уровень знатока/серия дней в «Моих результатах».
5. **MVP (текущая реализация):** каталог открыт без входа → вход → тренировка → результат → прогресс; гостевой режим и merge — следующий этап; без live, PvP, UGC, публичных рейтингов и мобильного приложения.
6. **Стек:** Next.js 16 + React 19 + TypeScript + Tailwind 4 + Prisma 7 + PostgreSQL; auth переиспользуем из `autocard-pro`.
7. **Контент:** 8 тем × 60 вопросов, 24 теста; темы и тон — под 45+/55+; импорт из `forms_writer` с факт-чеком и ревью.
8. **Главный риск:** не хватит глубины контента и удержания; митигация — банк вопросов, «тест дня», серия, повтор ошибок, диплом.
9. **Проверка:** закрытая бета 100–300 пользователей из Дзена и существующих каналов, юзабилити-тесты с людьми 55+, затем публичный запуск.

## 1. Контекст и предпосылки

### 1.1. Что уже есть

`forms_writer` умеет:

- генерировать вопросы через OpenAI-совместимый LLM;
- собирать тесты по 10–12 вопросов с 4 вариантами и одним правильным;
- делать фото-тесты и смешанные тесты;
- проверять факты, ревьюить тексты, дедуплицировать вопросы;
- публиковать анонсы в Telegram/VK и создавать формы в Яндекс Формах;
- публиковать тесты в Дзене — основном канале аудитории 45+/55+;
- вести состояние тестов и рубрик.

`autocard-pro` даёт проверенные паттерны:

- Next.js 16 App Router + React 19 + TypeScript + Tailwind 4;
- Prisma 7 + SQLite (в новом проекте рекомендуется PostgreSQL);
- собственная email-авторизация: scrypt, httpOnly-cookie `<userId>:<epoch>`, подтверждение email, сброс пароля, rate-limit, анти-брутфорс, согласия 152-ФЗ;
- админка с ролями, логирование с `requestId`, S3-совместимое хранилище, Docker/Caddy.

### 1.2. Чего не хватает

Яндекс Формы дают только «прошёл форму → увидел результат». Нет:

- истории и накопления прогресса по пользователю;
- прогресса по темам и отдельным вопросам;
- повторения ошибок и интервального повторения;
- ежедневных сессий и привычки возвращаться;
- собственной аудитории и аналитики поведения;
- гибких форматов (daily, review, live, duel);
- монетизации и B2B-сценариев.

### 1.3. Возможность

Сайт превращает разовый контент в **продукт с памятью**: пользователь не просто проходит тест, а строит карту знаний по темам, возвращается к слабым местам и видит рост. Контентный конвейер уже есть — это главное преимущество по скорости запуска.

## 2. Цель и метрики

### 2.1. Цель MVP

Запустить публичный сайт, на котором пользователь может:

1. без регистрации посмотреть каталог и выбрать тему;
2. после входа пройти тренировку на 10–30 вопросов за 5–10 минут;
3. получить результат с объяснениями и разбором ошибок;
4. видеть прогресс по темам и возвращаться к тому, что пора повторить.

### 2.2. North Star Metric

**WAQ-3** — число пользователей в неделю, прошедших ≥ 3 теста. Это лучше, чем DAU: отражает и привычку, и достаточную глубину.

Дополнительная продуктовая метрика: **число вопросов, переведённых в «освоено» за неделю** (суммарно по пользователям).

### 2.3. Метрики успеха MVP (первые 8–12 недель)

Ориентиры с поправкой на аудиторию 45+/55+:

| Метрика | Цель |
|---|---|
| Completion rate теста | ≥ 80% |
| Гость → первый завершённый тест | ≥ 70% |
| Гость → регистрация | ≥ 8% |
| D1 retention | ≥ 25% |
| D7 retention | ≥ 15% |
| D30 retention | ≥ 8% |
| Тестов на активного пользователя в неделю | ≥ 2 |
| Доля шарингов результата | ≥ 5% |
| Средняя точность | 60–75% |
| Доля пользователей с уровнем темы ≥ 3 за 30 дней | ≥ 20% |
| Доля пользователей с дипломом | ≥ 10% |

Эти цифры — гипотеза. Их нужно пересчитать после беты на 100–300 пользователях из Дзена и существующих каналов.

### 2.4. Не цели MVP

- Максимизация выручки.
- Замена школьной LMS.
- Live-игры и дуэли.
- UGC и социальная сеть.
- Публичные рейтинги и соревнование по скорости.
- Мобильное приложение в сторах.

### 3.2. Ключевые сценарии (JTBD)

1. **«С пользой провести 5 минут».** Открыл главную → нажал «Пройти тест» → ответил на 10 вопросов → увидел результат и объяснения → закрыл.

8. **«Организовать тест для команды»** (позже). Создал комнату → позвал по ссылке → увидел результаты.

## 4. Продуктовая концепция

### 4.1. Гибридная модель: выпуск + банк вопросов + прогресс

> **Терминология.** В коде, БД и API используем `Quiz`/«выпуск». В интерфейсе для пользователя — **«тест»**. Слова «квиз», «XP», «mastery», «лидерборд» в UI не показываем: для 55+ это «тест», «баллы», «освоено», «рейтинг» (если включён).

```
Тема (Topic)
 ├── Банк вопросов (Question)  ← освоение по каждому вопросу
 └── Выпуски (Quiz)            ← 10–12 вопросов, знакомый формат (позже)
        └── Попытка (Attempt)
              └── Ответы (AttemptAnswer) → обновляют освоение
```

**Почему не только «отдельные тесты»:**

- прогресс по тесту быстро заканчивается: прошёл — и всё;
- нельзя вернуться к ошибкам точечно;
- нельзя переиспользовать вопросы;
- невозможно показать «карту знаний».

**Почему не только «бесконечный банк»:**

- пользователю нужен понятный ограниченный формат «тест на 10–12 вопросов»; сейчас его роль выполняет тренировка на 10–30;
- тест удобно шарить и публиковать;
- без границ пользователь теряется и не видит финиш.

**Решение:** выпуск — единица потребления, вопрос — единица прогресса, тема — единица долгосрочной мотивации.

### 4.2. Пользовательский путь

```
Главная
  → «Продолжить тему» / «Тест дня» / «Выбрать тему»
    → Тренировка (10–30 вопросов, мгновенная проверка)
      → Результат (счёт, объяснения, +баллы, +% к теме)
        → «Повторить ошибки» / «Следующий тест» / «Отправить другу» (шаринг — позже)
          → Вход (если гость) → сохранение прогресса
            → «Мои результаты» → темы → тест дня → возврат завтра
```

### 4.3. Режимы игры

| Режим | MVP | Описание |
|---|---|---|
| **Классика** | ✅ | 10–30 вопросов, проверка после каждого, объяснение, без таймера |
| **Тест дня** | ⏳ Sprint 4 | 5–7 вопросов из разных тем, раз в день, бонус баллов |
| **Повтор ошибок** | ✅ | Вопросы с низким освоением + просроченные повторения |
| **Тест по теме** | ✅ | Тематический тест из каталога |
| **Экзамен** | ⏳ v1.1 | Все ответы в конце, без подсказок; таймер — опционально |
| **Бесконечный** | ⏳ v2 | Вопросы до первой ошибки, рекорд |
| **Live** | ⏳ v2 | Комната с ведущим, одновременная игра |
| **Дуэль 1×1** | ⏳ v2 | Асинхронный или реальный матч |

### 4.4. Формат вопроса (MVP)

- 4 варианта, один правильный;
- текст + опционально изображение;
- объяснение после ответа (1–3 предложения);
- источник/факт-чек для редакции (не всегда показывается пользователю);
- сложность 1–3;
- без таймера в классике (время фиксируется, но не наказывает);
- перемешивание вариантов на сервере;
- мгновенная обратная связь: цвет + иконка + текст (не только цвет).

## 5. Границы MVP

### 5.1. Входит в MVP

- Публичный сайт: главная, каталог тем, страница темы, страница теста, результат.
- Каталог открыт без входа; тренировки и прогресс — после регистрации. Гостевой режим (до 3 тестов) — следующий этап.
- Регистрация/вход по email, подтверждение email, сброс пароля, выход, смена пароля.
- «Мои результаты»: имя, аватар (инициалы/загрузка), статистика, история.
- Прогресс: вопрос → тема → глобальный.
- Баллы, уровень знатока, серия дней, 15–20 наград/значков.
- «Тест дня».
- Повтор ошибок.
- Диплом знатока темы (PNG/PDF/печать) после уровня 3 и 5.
- Карточка результата + шаринг в WhatsApp/ОК/VK/Telegram (OG-изображение + копирование ссылки).
- Крупная типографика, высокий контраст, режим увеличения текста.
- Админка: темы, вопросы, тесты, импорт JSON, публикация, базовая аналитика.
- Импорт контента из `forms_writer`.
- SEO-страницы тем и тестов.
- Правовой контур: политика, согласия, cookie-баннер, удаление аккаунта.
- Поддержка: жалобы на вопросы, FAQ, контактная форма.
- Аналитика: внутренние события + Яндекс Метрика/GA4 (по согласию).
- Docker-развёртывание, CI/CD, бэкапы, мониторинг.

### 5.2. Не входит в MVP

- Live-тесты, дуэли, матчмейкинг.
- Публичные рейтинги/лиги по умолчанию (только opt-in в v1.1).
- Соревнование по скорости и таймеры в классике.
- OAuth (VK/ОК/Яндекс/Telegram) — только email в MVP.
- Вход по коду из письма / телефону — v1.1.
- PWA/офлайн.
- Telegram Mini App.
- Мобильное приложение.
- UGC: пользовательские вопросы и публичные профили с лентой.
- B2B-кабинет учителя/компании, назначение заданий, отчёты по классу.
- Платежи, подписка, реклама.
- Мультиязычность (архитектурно закладываем, но контент — RU).
- Push-уведомления (только email/Telegram позже).
- Платные сертификаты и верификация дипломов.

### 6.6. Аккаунт и авторизация

**Базовое решение: переиспользовать подход `autocard-pro`, а не изобретать новый.**

Что копируем/адаптируем:

| Компонент `autocard-pro` | Что делаем в новом проекте |
|---|---|
| `lib/auth/password.ts` | scrypt (`scrypt$v$N$r$p$salt$hash`), политика длины и стоп-лист |
| `lib/auth/tokens.ts` | 32 байта random, в БД sha256, TTL verify/reset, одноразовость |
| `lib/auth/session.ts` | cookie `quiz_user_id` формата `<userId>:<epoch>`, httpOnly, SameSite=Lax, Secure в prod, 30 дней |
| `lib/auth/rateLimit.ts` | отдельные бакеты register/login/forgot/resend/verify; in-memory для одного инстанса, Redis при масштабировании |
| `lib/auth/identity.ts` | `emailNormalized` как источник истины, `AuthIdentity` для будущих OAuth |
| `lib/auth/authConfig.ts` | env-конфиг `AUTH_*`, `SMTP_*`, `MAIL_*` |
| `lib/auth/consent.ts` | версии документов, записи `Consent`, cookie-consent |
| `app/api/auth/*` | register, login, logout, logout-all, verify-email, resend, forgot, reset, change-password, change-email, me |
| `components/auth/*` | формы входа/регистрации/сброса, проверка пароля, статусы |

**Инварианты безопасности (обязательны):**

- нет user enumeration: одинаковый ответ на несуществующий email и неверный пароль;
- проверка состояния аккаунта — только после верного пароля;
- блокировка после 5 неудачных попыток на 15 минут;
- подтверждение email обязательно для входа (по умолчанию);
- пароли/токены/хеши никогда не логируются;
- смена пароля инвалидирует все сессии через `sessionEpoch`;
- rate-limit по email и IP на каждую операцию;
- CSRF-защита: SameSite=Lax + проверка Origin для state-changing запросов;
- админские роуты — `requireAdmin`.

**Отличия от `autocard-pro`:**

- cookie называется `quiz_user_id`;
- нет энергии/биллинга/обработки фото;
- позже добавляется гостевой режим и merge прогресса;
- добавляется `UserStats`, `TopicProgress`, `QuestionProgress`;
- OAuth (VK/ОК/Яндекс/Telegram) — v1.1, модель `AuthIdentity` уже готова;
- для мобильного приложения позже — bearer-токены/refresh-токены через отдельный слой, не ломая cookie-сессии веба.

**Поправка на аудиторию 55+:**

- регистрация максимально короткая: email + пароль + согласия, **без телефона и даты рождения**;
- пароль 8+ символов и стоп-лист, без требований к регистру/спецсимволам;
- «Показать пароль» по умолчанию доступно, крупные поля и понятные ошибки;
- «Забыли пароль?» — крупная заметная ссылка на экране входа;
- после регистрации — автоматический вход, сессия 30 дней, «запомнить меня» по умолчанию;
- подтверждение email — да, но с понятным письмом и повторной отправкой;
- тексты: «Сохранить результаты», а не «Зарегистрироваться»;
- письма должны доходить до Mail.ru, Яндекс Почты и Rambler: SPF/DKIM/DMARC, репутация домена, тест на реальных ящиках;
- пароль можно не требовать при входе по коду из письма (v1.1) — это снимет главный барьер «забыл пароль».

**Требования:**

| ID | Требование | Приоритет |
|---|---|---|
| AUTH-1 | Регистрация email + пароль + согласия | Must |
| AUTH-2 | Подтверждение email по ссылке, повторная отправка | Must |
| AUTH-3 | Вход/выход, «выйти на всех устройствах» | Must |
| AUTH-4 | Забыл пароль / сброс по email (заметная ссылка) | Must |

### 6.7. Гостевой режим и merge (отложено)

**Решение Sprint 2 (C24):** в текущей реализации каталог и темы открыты без входа,
но тренировка, ответы и прогресс требуют аккаунта. Гостевой режим и merge
прогресса перенесены на следующий этап: они требуют отдельной модели анонимной
сессии, защиты от повторного merge и пересчёта прогресса, а первый учебный цикл
можно проверить без них.

**Что будет позже (проект):**

1. При первом визите создаётся `User` с `isGuest=true` и подписанной cookie
   `quiz_guest_id` (httpOnly, 30 дней) либо отдельная таблица `GuestSession`.
   Предпочтителен `User.isGuest` — проще merge.
2. Гость может пройти до 3 тестов / 24 часа (настраиваемо).
3. Прогресс, попытки и ответы пишутся в БД как обычно.
4. После 2-го теста или при попытке открыть «Мои результаты»/историю показывается
   мягкий CTA «Сохранить результаты».
5. При регистрации/входе гостевые данные переносятся на аккаунт в транзакции:
   `Attempt.userId`, `QuestionProgress`, `TopicProgress`, `DailyActivity` — merge;
   при конфликте по вопросу берём более высокое освоение и более поздний
   `lastSeenAt`; баллы и статистика пересчитываются; гостевой `User`
   удаляется или помечается merged.
6. Cron удаляет неактивных гостей старше 30 дней.

**Ограничения:** merge должен быть идемпотентным; нельзя допустить повторный
перенос одного и того же гостевого прогресса.

## 7. Контент-модель и требования

### 7.1. Иерархия

```
Категория (Category) — «Кино», «География», «История», «Природа»
  └── Тема (Topic) — «Советское кино», «Столицы мира», «История России»
        ├── Вопросы (Question) — банк
        └── Выпуски (Quiz) — 10–12 вопросов
```

Для MVP достаточно одного уровня тем, но модель должна поддерживать родителя (Category → Topic), чтобы позже не мигрировать.

### 7.2. Требования к теме

- название и slug;
- короткое описание (1–2 предложения) и SEO-описание;
- обложка;
- минимум **50 вопросов** для полноценного прогресса (цель — 80–120);
- 3–10 тестов на старте;
- сложность (1–3);
- статус (draft/published/archived);
- соответствие возрастной аудитории: без политики, религии, медицинских советов и современной поп-культуры.

### 7.3. Требования к вопросу

- один правильный ответ (для MVP);
- 4 варианта, сопоставимая длина, без «все вышеперечисленное»;
- без отрицательных формулировок и двусмысленностей;
- объяснение 1–3 предложения — обязательная часть, а не опция;
- источник/факт-чек (для редакции);
- изображение — только с лицензией и атрибуцией, с alt-текстом;
- сложность 1–3;
- теги;
- `content_hash` для дедупа;
- версия: опубликованный вопрос нельзя редактировать «на лету» — исправление создаёт новую версию, старая архивируется (иначе прогресс и история становятся нечестными).

### 7.4. Требования к выпуску (тесту)

- 10–12 вопросов;
- один тематический фокус;
- порог прохождения (например, 70–80%);
- интро (1–3 абзаца) и аутро (1–2 абзаца) без давления и кликбейта;
- сегменты результата: «Можно лучше», «Хороший результат», «Уверенный», «Знаток» (без обидных формулировок);
- обложка и SEO-описание;
- дата публикации;
- автор/редактор;
- статус.

### 7.5. Объём контента для MVP

Минимум для запуска:

- **8 тем** × **60 вопросов** = **480 вопросов**;
- **24 теста** (по 3 на тему) × 10–12 вопросов;
- 2–3 фото-темы (кино, живопись, породы собак) — как в `forms_writer`.

Темы старта: история России и СССР (без политики), советское и классическое кино, актёры, песни и музыка, литература, география, природа и животные, кулинария и традиции, быт и ностальгия.

Этого хватит, чтобы у пользователя было 3–5 сессий по каждой теме и ощущение прогресса.

### 7.6. Формат импорта из `forms_writer`

Предлагаемый JSON (близок к текущему `samples/questions.json`):

```json

  "pass_threshold": 8,

    {
      "external_id": "q-cinema-001",
      "type": "image_single_choice",
      "text": "Из какого фильма этот кадр?",
```

## 8. Архитектура и стек

### 8.1. Рекомендуемый стек

| Слой | Выбор | Почему |
|---|---|---|
| Frontend/Backend | **Next.js 16 App Router + React 19 + TypeScript** | Тот же стек, что в `autocard-pro`; SSR/SEO; один деплой |
| Стили | **Tailwind CSS 4** + headless-компоненты (Radix/shadcn по необходимости) | Скорость и доступность |
| ORM | **Prisma 7** | Знакомый инструмент; миграции |
| БД | **PostgreSQL 16** (prod), SQLite — только локально | Конкурентность, рейтинги, аналитика, рост |
| Auth | Собственный слой, адаптированный из `autocard-pro` | Проверено, без лишних зависимостей |
| Валидация | **Zod** | Публичный API и импорт контента |
| Email | **Nodemailer + SMTP/ESP** (Unisender/Sendsay/SendPulse) | RU-провайдеры, dev-фолбэк в лог |
| Изображения | S3-совместимое хранилище (Yandex/VK Object Storage) + CDN | Фото-вопросы и аватары |
| Фоновые задачи | GitHub Actions/cron + отдельный worker-контейнер | Ежедневный контент, дайджесты, очистка |
| Тесты | Vitest + Playwright | Юнит и e2e |
| Мониторинг | Sentry + структурные логи + `/health` | Диагностика |
| Деплой | Docker Compose (Next + Postgres + Caddy) на VPS в РФ или Vercel + Neon (решение) | 152-ФЗ и контроль |

> **Важно по Next.js 16:** версия содержит breaking changes относительно привычных версий. Перед началом разработки нужно прочитать документацию в `node_modules/next/dist/docs/` (как указано в `autocard-pro/AGENTS.md`) и не полагаться на память.

### 8.2. Архитектурный стиль

- **Монолит Next.js** на MVP: проще, дешевле, быстрее.
- **REST API `/api/v1`** для публичных данных и будущего мобильного приложения.
- **Server Actions** — для внутренних мутаций веба (профиль, настройки), где удобно.
- **Серверная проверка ответов** — обязательна; клиент не получает правильные ответы до ответа.
- **Слой сервисов** (`lib/quiz`, `lib/progress`, `lib/content`, `lib/auth`) — чтобы позже вынести API/мобильный бэкенд.
- **Событийная аналитика** — через единый `track()` с очередью/батчем.

### 8.3. Схема компонентов

```
Браузер (Next.js RSC + client components)
   │
   ├── /api/v1/*  (REST, JSON, cookie-сессия)
   │      ├── content: topics, quizzes, questions (без ответов)
   │      ├── attempts: start, answer, finish
   │      ├── me: stats, history, progress, achievements
   │      └── auth: register/login/verify/reset/...
   │
   ├── PostgreSQL (Prisma)
   ├── S3/Object Storage (изображения)
   ├── SMTP/ESP (письма)
   └── Analytics (Метрика/GA4) + Sentry
```

### 8.4. Масштабирование

| Этап | Что делаем |
|---|---|
| MVP (до 10k DAU) | Один инстанс Next + Postgres + Caddy; in-memory rate-limit; индексы; CDN для медиа |
| Рост (10–50k DAU) | Redis для rate-limit/кэша/рейтингов; read-replica; вынос фонового worker |
| 50k+ DAU | Горизонтальное масштабирование Next; очередь (BullMQ/Redis); отдельный analytics-store; CDN |

### 10.4. Auth

`POST /api/v1/auth/register`, `login`, `logout`, `logout-all`, `verify-email`, `resend-verification`, `forgot-password`, `reset-password`, `change-password`, `change-email`, `GET /api/v1/auth/me`. Контракты — по образцу `autocard-pro`.

### 10.5. Админка

`/api/v1/admin/topics`, `questions`, `quizzes`, `import`, `users`, `analytics`, `reports`. Все — `requireAdmin`/`requireEditor`, аудит.

### 10.6. Общие правила

- Формат ошибки: `{ error: { code, message, details? }, requestId }`.
- `X-Request-Id` — сквозной, из заголовка или сгенерированный.
- Пагинация — cursor (`?cursor=...&limit=20`).
- Идемпотентность ответов/финиша — `Idempotency-Key`.
- Версионирование API — `/api/v1`.
- OpenAPI-спека — генерировать из Zod-схем (или вести вручную).
- Мобильный клиент позже использует те же endpoints + bearer-токены.

## 12. UX/UI

### 12.1. Принципы

1. **Один вопрос — один экран.** Никаких простыней.
2. **Крупно и понятно.** Читаемый текст, большие кнопки, высокий контраст.
3. **Спокойный темп.** Без таймера, без автоперехода, без звуков по умолчанию.
4. **Мгновенная обратная связь.** Цвет + иконка + короткое объяснение.
5. **Прогресс виден, но не давит.** Полоса вопроса, а не 20 счётчиков.
6. **Финиш понятен.** Результат, что дальше, чем поделиться, как получить диплом.
7. **Ноль трения на входе.** Каталог и темы доступны без регистрации; тренировка требует входа. Гостевой режим — следующий этап.
8. **Уважение.** Никакого сленга, снисходительности и публичного сравнения по умолчанию.
9. **Честность.** Не показывать «100% знаний» после одного теста.

### 12.4. Экран вопроса

- Верх: «Вопрос 3 из 12», полоса прогресса, кнопка «Выйти» с подтверждением.
- Вопрос: крупный текст 20–24 px, изображение (если есть) с alt-текстом.
- 4 варианта: кнопки высотой ≥ 56 px, буквы A–D, расстояние ≥ 12 px.
- После ответа: подсветка, иконка + текст, объяснение, кнопка «Далее».
- Неверный ответ: показать правильный + объяснение, без осуждения.
- Автопереход не делать: пользователь должен успеть прочитать объяснение.
- Внизу — «Продолжить позже»: прогресс сохраняется.

### 12.5. Экран результата

- Крупно: `10/12` и спокойный сегмент («Хороший результат»).
- Баллы, серия дней, прирост по теме.
- Разбор: список вопросов, фильтр «только ошибки».
- Кнопки: «Повторить ошибки», «Следующий тест», «Отправить другу».
- Если достигнут уровень 3/5 — блок «Ваш диплом готов» со скачиванием и печатью.
- Если гость: кнопка «Войти и сохранить результаты» → вход/регистрация с объяснением пользы (гостевой прогресс — позже).

### 12.6. «Мои результаты»

- Верх: аватар, имя, уровень знатока, баллы, серия дней.
- Heatmap активности за 12 недель — спокойная, без соревнования.
- «Ваши темы»: карточки с изученностью/точностью/уровнем.
- «Слабые места»: N вопросов на повтор.
- «Последние попытки».
- «Награды» и «Дипломы».
- Кнопка «Увеличить текст» доступна на всех экранах.

### 12.7. Дизайн-система

- Цвета: спокойный основной акцент, успех, ошибка, нейтральные; без кислотных сочетаний.
- Типографика: крупная, читаемая; основной текст 18–20 px, варианты 20–22 px.
- Шрифты: Golos Text, PT Sans, Inter или Source Sans; без тонких начертаний.
- Компоненты: Button, Card, ProgressBar, TopicCard, TestCard, OptionButton, Badge, Modal, Toast, Skeleton.
- Иконки: единый набор, всегда с текстовой подписью для важных действий.
- Анимации: сдержанные, 150–250 мс; уважать reduced motion.
- Никаких мелких крестиков, свайпов, drag-and-drop и скрытых меню.

## 13. Интеграции

### 13.1. `forms_writer` → сайт

**Вариант A (MVP): экспорт JSON + ручной импорт.**

- Добавить в `forms_writer` режим `--export-site` / `--site-json`, который пишет файл в формате из §7.6.
- Админка принимает файл, валидирует, показывает предпросмотр, публикует.
- Плюс: минимум изменений, контроль качества.
- Минус: ручной шаг.

**Вариант B (v1.1): webhook/API.**

- `forms_writer` после ревью и факт-чека отправляет выпуск в `POST /api/v1/admin/import` с API-ключом.
- Сайт создаёт draft, редактор подтверждает.
- Плюс: автоматизация; минус: нужен API-ключ и защита.

**Рекомендация:** A для MVP, B после стабилизации.

### 13.2. Дзен, Telegram, VK, Одноклассники

- **Дзен — главный канал.** Публикуем тесты/статьи, в конце — мягкий CTA «Продолжите на сайте: там сохраняется прогресс и можно вернуться к ошибкам». UTM-метки на все ссылки, ссылка в профиле.
- Telegram/VK/ОК — публикация анонса нового теста (уже есть в `forms_writer`).
- Для 55+ Одноклассники и WhatsApp важнее Telegram.
- Ссылка ведёт на сайт, а не на Яндекс Форму.
- Позже: Telegram-бот с «тестом дня» и уведомлениями; Mini App.

### 13.3. Email

- Транзакционные письма: verify, reset, change email.
- Дайджест прогресса и «тест дня» — только opt-in.
- ESP: Unisender/Sendsay/SendPulse; SMTP + Nodemailer.
- Доставка в Mail.ru, Яндекс Почту и Rambler: SPF/DKIM/DMARC, прогрев домена, тест на реальных ящиках.
- Письма короткие, крупный шрифт, одна понятная кнопка.
- Dev-фолбэк: письмо в лог, UI «отправлено».

### 13.4. Аналитика

- Яндекс Метрика (RU), GA4 (опционально).
- Внутренние события в БД/аналитическое хранилище.
- Consent-gated загрузка.
- UTM-разметка ссылок из Дзена, Telegram, VK, ОК, WhatsApp.

### 13.5. Монетизация (позже)

- В MVP монетизации нет.
- Реалистичные варианты для аудитории 45+/55+:
  - аккуратная реклама без раздражающих форматов;
  - партнёрские/спонсорские тесты («Тест от библиотеки», «Тест от музея»);
  - B2B: школы, библиотеки, музеи, социальные программы, компании;
  - премиум без рекламы — как опция, не как основа.
- Платежи: ЮKassa/CloudPayments (РФ), Stripe — при выходе на международный рынок.
- Не строить платежи до подтверждённого удержания и спроса.

## 15. Риски и меры снижения

| Риск | Вероятность | Влияние | Мера снижения |
|---|---|---|---|
| Мало контента для прогресса (в теме только 10–12 вопросов) | Высокая | Высокое | Минимум 50–60 вопросов на тему; банк вопросов; конвейер `forms_writer` |
| Низкое качество LLM-вопросов | Средняя | Высокое | Обязательный факт-чек, ревью, редактор, жалобы пользователей; для истории/кино — двойная проверка |
| Слабое удержание после первого теста | Высокая | Высокое | «Тест дня», серия дней, свежий контент, прогресс по темам, диплом |
| Холодный старт аудитории | Средняя | Высокое | Дзен как основной канал, ОК/VK/Telegram, SEO, шаринг в WhatsApp |
| Мелкий текст/неудобный интерфейс отпугивает 55+ | Высокая | Высокое | Крупная типографика, контраст, большие кнопки, тесты с реальными пользователями |
| Email-барьер и забытые пароли | Высокая | Высокое | Guest-first, простой сброс, позже вход по коду/телефону; письма доходят до Mail.ru/Яндекс/Rambler |
| Публичное сравнение демотивирует | Средняя | Среднее | Рейтинги только opt-in; по умолчанию — личный прогресс |
| Читерство в будущих рейтингах | Средняя | Низкое | Серверная проверка, минимальное время, аномалии; в MVP не критично |
| Юридические риски (152-ФЗ, изображения, возраст) | Средняя | Высокое | Консультация юриста, лицензии, согласия, хранение в РФ |
| Расползание скоупа (live, PvP, UGC) | Высокая | Среднее | Жёсткие границы MVP, phase gates |
| Технические проблемы Next.js 16 | Низкая | Среднее | Читать docs, следовать паттернам `autocard-pro`, тесты |
| Зависимость от одного разработчика | Средняя | Среднее | Документация, тесты, CI, код-ревью |
| Монетизация не взлетит | Средняя | Среднее | Валидировать B2B/рекламу/партнёрские тесты после MVP, не строить платежи заранее |
| Спам/боты в регистрации | Средняя | Среднее | Rate-limit, email verify, honeypot, captcha при аномалиях |

## 18. Итоговое предложение

1. **Не делать «просто сайт с тестами».** Сделать сервис с памятью: вопрос → тема → «Мои результаты».
2. **Проектировать под 45+/55+ с первого экрана:** крупный текст, высокий контраст, большие кнопки, спокойный темп, уважительный тон.
3. **Использовать гибрид:** тренировки 10–30 вопросов + банк вопросов + прогресс по темам; готовые выпуски — позже.
4. **Пускать без трения:** каталог открыт без входа, тренировка — после простой регистрации; auth переиспользуется из `autocard-pro`; гостевой режим с merge — следующий этап.
5. **Начать с 8 тем × 60 вопросов** и 24 тестов; контент — из `forms_writer`, с обязательным факт-чеком.
6. **В MVP — только личный прогресс, «тест дня», серия, награды, диплом и шаринг в WhatsApp/ОК.** Live, PvP, UGC, публичные рейтинги и B2B — позже.
7. **Дзен — главный канал дистрибуции**, дальше ОК, VK, Telegram, WhatsApp и SEO.
8. **Мерить WAQ-3, completion rate, D1/D7, guest→registration, долю шарингов и долю дипломов.**
9. **Проверить гипотезу на закрытой бете 100–300 пользователей из Дзена**, обязательно — юзабилити-тесты с людьми 55+, затем открывать публично.
